# UI and localization

- Match the project's existing design tokens, components, content voice, and interaction patterns. Do not introduce a second palette or component system without a reason from the task.
- Check the affected normal, loading, empty, error, disabled, hover, and focus states where they exist. Ensure usable keyboard interaction, readable text, and responsive layout for the changed surface.
- When the product has multiple locales, update the relevant dictionaries and placeholders together. Test direction, number/date formatting, and layout behavior where the change touches them. Do not hardcode one locale into a reusable component.
- Verify visible changes in a rendered UI when the project's tools are available. State plainly when visual or interaction checks could not be run.
