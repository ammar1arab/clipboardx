# Change plan

Read enough of the current project to identify the affected flow, contracts, and constraints. State the goal, smallest scope, main risks or open decisions, and how success will be verified.

Keep the plan proportional to the task. Use concrete file or layer names only after observing them. Do not demand a plan for a trivial edit or treat planning as an automatic approval gate. Continue authorized work unless a material requirement or consequential action genuinely needs user input.

If the plan changes during implementation, update it only where that affects scope, risk, or verification.
