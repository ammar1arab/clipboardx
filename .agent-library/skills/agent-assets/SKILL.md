# Agent assets

Read the current root entry point, catalog, canonical files, and relevant editor adapters. Identify which instruction is universal, project-specific, host-specific, or temporary before editing.

Keep one canonical body. Give each skill a specific trigger, a useful decision process, and a completion check. Keep always-on rules short. Do not add absolute bans, model choices, tool mandates, or approval gates without a demonstrated project need and current host support.

After editing, validate frontmatter, relative links, duplicate triggers, and references to removed paths. Check actual discovery in each targeted host when accessible; otherwise document manual invocation. Never store credentials, private data, or one-time authorization in persistent guidance.
