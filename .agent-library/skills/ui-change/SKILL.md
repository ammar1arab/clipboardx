# UI change

Inspect the affected screen, a nearby comparable screen, and the project's design source. Identify the requested visual or interaction outcome before editing. Reuse existing components, tokens, typography, and motion patterns unless the user supplied a new direction.

Implement the requested states and behavior with a focused diff. Check keyboard and touch interaction where applicable, focus visibility, readable contrast, narrow layouts, and reduced motion or RTL when supported by this surface.

Render and exercise the changed UI with the project's available tools. Check a representative wide and narrow viewport or device class. Report what was observed; a successful build alone does not establish visual quality.
